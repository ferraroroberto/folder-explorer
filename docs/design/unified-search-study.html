One app for disk, folders and email archive

The plan for folder-explorer#6: fold email-archiver and the folder searcher into folder-explorer. Updated after the owner's answers of 2026-11-05. This is research only; no code was changed. Every name, address and path below is invented.

The plan. Folder-explorer becomes the only app (shape A, full fold), built in three steps that each ship on their own. Step 1 adds read-only search. Step 2 builds one scan engine that owns the email index. Step 3 adds the Outlook actions and retires email-archiver. One metadata walk feeds the disk sizes, the folder search and a list of .msg files. An opt-in email stage then reads the new and changed .msg files under the configured email folders, and it may download online-only ones. That stage, plus the on-demand "Show all" in the preview, are the only places the "never open a file" rule makes an exception, and both go through one reader module. task-os and life-os both drive email-archiver today, through its index file, its batch CLI, its config loader and its venv. Each step keeps those contracts working, and both are retargeted together in step 3.

The shape: full fold

email-archiver's package (scanner, FTS search, suggester, archiver, Outlook COM, batch verbs, mailbox registry, naming rules) and the folder searcher's query logic move into folder-explorer as src/email/, src/outlook/ and src/folder_search.py. A web sheet replaces the Tk archive dialog, with a fallback window for when the app isn't running. email-archiver is archived at the end of step 3.

  • Indexes: all in folder-explorer's runtime-data folder. The per-scan disk indexes stay as they are. emails.sqlite3 stays one incremental WAL database with today's schema plus additions, because re-reading every .msg takes hours.
  • One writer. Only folder-explorer's email package writes emails.sqlite3: the email stage and the ported renumber. Every other consumer opens it mode=ro.
  • Optional parts: each part has its own requirements file: requirements-email.txt (extract-msg, rapidfuzz, pyyaml while a life-os script needs it) and requirements-outlook.txt (pywin32, psutil). A part turns on when its config is set and its imports resolve. Otherwise it shows "Not set up here: reason", never an empty result.
  • Work PC: one checkout, one venv, one gate, one tray. A plain git pull brings everything, and the local config.json decides which parts run.

Considered and set aside: B, email-archiver as an imported library (two checkouts that must stay on matching commits at work); C on its own, read-only search with archiving left in email-archiver (kept only as step 1); D, a shared core package (a fourth repo, the opposite of one app).

One scan engine

walk (metadata only, today's winfs listing)            ── one pass per root, disk-walk lock
  ├─ disk index      folders / files / folder_ext         (unchanged)
  ├─ folder search   folders + full-path column, FTS5 trigram for substring match
  └─ email manifest  every *.msg under an email folder: path, size, mtime, online-only?
                         │
                         ▼
email stage (opt-in, child process, email-index writer lock)
  diff manifest against emails.sqlite3 by (path, size, mtime)
  ├─ unchanged            → skip (no file touched)
  ├─ new/changed, local   → read through src/email/reader.py, upsert, FTS triggers
  ├─ new/changed, online  → read (downloads it) while the run's download budget lasts,
  │                         else count "waiting for budget"
  ├─ failed before        → skip until its (size, mtime) changes, so no re-download
  └─ gone (only after a COMPLETE walk of that folder) → purge rows
  • Folder search is a query, not a scanner. The walk already records every folder's name and parent. Derive the full path per folder, with an FTS5 trigram index for substring match. Port the behaviours, not the code: AND of terms split on whitespace and ;, email-branch pruning (a folder with a direct child named like someone@example.com becomes a leaf result), and the display-only skip-N-leading-components setting.
  • Two locks, one history. The disk walk and the email index each have a lock. The nightly run takes them in turn. A scoped email index --root <folder> takes only the email lock and walks only that folder, so the re-index a consumer asks for after filing a mail takes seconds and doesn't wait behind a multi-hour disk walk. Each stage writes its own row in state.sqlite3: "disk ok · emails 37 new (12 downloaded, 48 MB), 3 waiting for budget".
  • Busy is its own state. If the email lock is held past the caller's timeout, the scoped run exits with a distinct "busy" code, never a plain failure.
  • Exclusions (merge item 1) apply at the walk, so disk, folder search and emails all skip the same paths.

The .msg reading boundary (Q2: allow download)

The disk walk, folder search and the Explore, Largest and Types tabs keep the rule absolute: they never open a file. Email indexing, "Show all" and "Open in Outlook" are the only paths that may read a .msg, and reading an online-only one downloads it. The boundary below keeps that exception narrow, visible and testable.
RuleHow it holds
Where: only *.msg under email.rootsA config list. Each folder must sit inside a scan root, and config load refuses any that doesn't. Nothing outside those folders is ever read, whatever its extension.
Who: one reader modulesrc/email/reader.py is the only module that imports extract_msg or opens a scanned file. A unit test (or a conventions-ratchet rule) fails the gate if any other module does. The walk's existing "no per-file handle" tests stay.
When: new or changed onlyDecided by the manifest diff on (path, size, mtime). An unchanged file is never touched. A failed read is logged in email_failures(path, size, mtime, reason) and isn't retried until the file changes, so one bad file never downloads every night.
How: read-onlyThe file is opened for reading only. Nothing writes to it, and nothing changes its attributes, pin state or timestamps. No attrib, no OneDrive pin or unpin.
How much: a download budgetemail.download_budget_mb per run (proposed default 2048; 0 means local-only). The first full index then spreads over several nights instead of pulling the whole archive at once. Online-only state comes from the listing's attributes, so the count needs no extra call.
Where it runs: a child processThe email stage runs as python -m app.cli email index with CREATE_NO_WINDOW, and "Show all" uses a child with a timeout. The long-lived web server never blocks on a download.
Visible: counted and reportedThe Scans tab shows files downloaded, MB downloaded, waiting for budget and failed, each as its own number. README and CLAUDE.md state the exception in one sentence per part, in the same PR that lands the reader.

A side effect to state plainly: a downloaded file stays on the disk until OneDrive's Storage Sense or "Free up space" removes it, so local disk use grows by the size of the archive's mail. The Explore tab shows that growth like any other folder. Folder-explorer doesn't send files back to online-only, because changing a file's state is a write.

What gets built

  1. One Search tab with a Folders | Emails segmented control. The mode lives in the URL (#search?mode=emails&q=…), and the box keeps its text when you switch.
  2. Gmail-style operators, parsed to SQL + FTS5, with chips as the main interface and syntax for power use. Every chip writes its operator into the box, so the two always match:

  3. Facets with counts over the current result set: top senders, top archive folders, a year and month strip, attachments, flagged.
  4. The preview pane (Q6). On desktop, the list sits on the left and the reading pane on the right (a declared wide view, like Explore). On the phone, tapping a result opens a full-height sheet. The pane shows:
    • the header fields and the indexed 500-character preview, with matches marked (FTS5 highlight()), plus the attachment names;
    • Show all (key a), which calls GET /api/emails/{row id}/body. The server looks up the path by row id (never a path from the client), checks that it sits under an email folder, and reads it through the reader in a child process with a timeout. It returns the plain-text body. An HTML body is sanitised and shown in a sandboxed frame with scripts and remote loads blocked, so tracking images never fire. Bodies aren't stored in the index or cached on disk.
    • For an online-only file, the button reads "Show all · downloads from OneDrive". A read that fails says why, with a distinct message for each case: download timed out, file no longer there, could not be parsed. A successful read logs one info line, and a failed one logs the reason.
    • Show all works for any signed-in client, phone included, because it is a read behind the app's existing login and the download happens on the PC. Open in Outlook stays PC-only (Q5).
    • Actions: Open in Outlook (PC), Show folder, Copy path, Find in mailbox (the live copy by Message-ID).
  5. Sort by relevance (BM25, ties go to the newest) or by newest first.
  6. Saved and recent searches: saved queries appear as chips, stored in state.sqlite3, and relative dates stay relative. The last 10 queries show when the box is empty.
  7. Keyboard: / focuses the box, ↓ or j/k move, Enter previews, a shows all, o opens in Outlook, f shows the folder and Esc goes back. The keys match task-os.

The Outlook bridge

The macro (Q10: fire and forget)

' Template shipped in the repo (no paths inside); the user imports it once.
Sub ArchiveCurrentItem()
    Dim it As Object, home As String, cmd As String
    If TypeName(Application.ActiveWindow) = "Inspector" Then
        Set it = Application.ActiveInspector.CurrentItem      ' an opened mail
    ElseIf Application.ActiveExplorer.Selection.Count > 0 Then
        Set it = Application.ActiveExplorer.Selection.Item(1)  ' the selected mail
    Else
        Exit Sub
    End If
    home = Environ$("FOLDER_EXPLORER_HOME")                   ' set once per PC
    cmd = """" & home & "\.venv\Scripts\pythonw.exe"" -m app.outlook archive" _
        & " --entry-id " & it.EntryID & " --store-id " & it.Parent.StoreID
    CreateObject("WScript.Shell").Run cmd, 0, False            ' hidden, do not wait
End Sub
  • The path comes from one per-PC environment variable, so the macro is the same at home and at work. pythonw.exe has no console. Children the Python side starts get CREATE_NO_WINDOW through src/no_window.py.
  • IDs are passed at click time. Python re-acquires the mail with Session.GetItemFromID(entry, store) after attaching with GetActiveObject. That avoids archiving the wrong mail after a fast click, and it handles an opened mail as well as a selected one.
  • No wait means the macro never blocks Outlook's single-threaded object model while the child makes COM calls into it.
  • Feedback comes from the Python side: the archive sheet or the fallback window, or a toast with failures in their own words ("Outlook not reachable" is a different message from "no archive root mounted").
  • COM rules carry over: attach and never start a hidden Outlook from the bridge; resolve Exchange senders with GetExchangeUser(); run every COM call in a child process with a timeout, never in the web server.
  • riskNew Outlook for Windows supports neither VBA nor COM. If the work PC moves to it, the macro and every COM verb stop working.

"Open in Outlook" (Q5: PC only)

  • It opens the archived .msg, not the live mail, because a mail's EntryID changes whenever it moves. The server runs outlook.exe /f "<path>" on the PC with CREATE_NO_WINDOW. The route takes a row id and accepts loopback clients only. An online-only file downloads first, and the button says so.
  • Find in mailbox reuses the find / plan --message-id path, which looks up the live copy by its Message-ID header and calls Display() on it.

Build steps

Each step is its own issue and PR and ships on its own. The mock-up is issue #7.

Step 1. Read-only search, with Show all

  • A Search tab with Folders | Emails, operators, chips, facets, the preview pane, saved and recent searches, and the keyboard flow.
  • Email search reads email-archiver's current emails.db with mode=ro, through a new email.index_path setting. Folder search runs over folder-explorer's own index, with pruning and the skip-N display.
  • Show all lands here, so src/email/reader.py, the "only the reader opens a file" test, the email.roots check, the child process with its timeout, and the README and CLAUDE.md wording of the exception all ship in this step. Adds requirements-email.txt.
  • Consumers: nothing changes for task-os or life-os.

Step 2. One scan engine; the index moves

  • The walk produces the .msg manifest and applies exclusions. The email stage takes over indexing: Windows-1252 recovery, the Q8 columns with one forced re-read, the download budget, email_failures, the two locks, and a scoped email index --root.
  • emails.sqlite3 now lives in folder-explorer's runtime-data folder, with folder-explorer as its only writer (the scanner and renumber move over). It keeps today's columns and FTS column order.
  • Consumers, in the same release: task-os's search.email_db is repointed. email-archiver's database.path is repointed too, so its plan/find/suggester and life-os's config probe and extract_sent.py read the new file without any change to life-os. email-archiver's main_scan.py becomes a shim that runs folder-explorer's scoped email index, so life-os's re-index after filing keeps working. The nightly chain becomes life-os sweep → folder-explorer scan → folder-searcher headless scan. The folder-searcher tray app retires, but its headless scan stays because life-os's folders verb still reads its file.

Step 3. Outlook actions; email-archiver retires

  • The archive suggester (exact-subject priority, Q7 ranking), the archive sheet with its fallback window, the VBA bridge, Open in Outlook, the mailbox registry, and every batch verb under python -m app.cli email batch, with the same JSON, error codes and exit codes. Adds email config --json and folders search --json. The contract test from the consumers section is part of the gate.
  • task-os: retargeted to app.cli email batch under folder-explorer's venv.
  • life-os, in one PR that lands with this release: mailtool/archiver.py (repo variable, venv, batch argv, config probe, re-index), the folders lookup (CLI instead of the text file), the sweep .bat interpreter, extract_sent.py's interpreter, the archive skill's .msg reader table, and email_test_support.py.
  • Then the folder searcher's headless scan job retires. The main_scan.py shim and the old variable fallback stay for one release, and then email-archiver is archived.
