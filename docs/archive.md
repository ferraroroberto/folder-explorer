# Archive: the sheet, the macro and the verbs

How mail is filed into the email folders: the Archive sheet in the web app, the Outlook macro, and the headless verbs another app drives. Everything here writes only inside `email.roots`.

## Archive sheet and the Outlook macro (this PC)

**Archive the open mail**, the first card on Search in email mode, opens the Archive sheet for the mail open or selected in Outlook (classic): a collapsible preview of its readable text; its suggested folders, ranked, each with its % match (a weak guess below 35% is marked), why (same email, same subject, sender, topic: a folder already holding a copy with this mail's Message-ID leads at 100% as **Same email**, then folders holding this very subject, found apart from the search ranking so a crowded-out thread folder still leads), how many similar mails the folder holds with one example subject, and an Open button that shows the folder in File Explorer (looked up by its place in the last disk scan, never by a path from the page); **Find a folder**, the window's own search: Quick search's matcher and the `folder_search` options over every scanned folder, the email folders first, and a folder outside them listed greyed as **Outside the email folders**, to step into or open but never to file in. Tapping a folder selects it (one inside the email folders also becomes the chosen folder), **Archive here** files the mail there at once with the sheet's category, copy and date-prefix choices, **Open in File Explorer** shows it, and the `›` beside a folder steps into its subfolders from the last scan (`GET /api/archive/subfolders`, the PC only, looked up by root, scan id and folder id, never by a path; a breadcrumb names the way down and the back arrow steps up); **Current Explorer folder**, which offers the folder open in the front File Explorer window with its whole path (the server asks Windows through the bridge's `explorer` verb, so it works for a page on this PC only; a folder outside the email folders is refused, and "Cannot read Explorer windows" and "No Explorer folder is open" are different messages); the Outlook category (or none), a row that shows only while the **Add an Outlook category when archiving** switch in Settings is on (`outlook.add_category`, off unless set): with it off, neither the sheet nor the window shows the row and the bridge's `file` stamps nothing, whatever category it is sent, and the batch verbs' own `--category` is unchanged; the date prefix (**Auto** follows `archive.date_prefix` and the folder's own names, **On** or **Off** for this mail only, sent as `date_prefix` and to the bridge's `file` as `--date-prefix`); and the file name it will get. Every path the app shows uses `\` separators; stored paths keep whatever form they have. **Archive** saves the `.msg` and its attachments into that folder, and the sheet or window closes the moment the `.msg` is confirmed on disk; tagging the mail and queuing its folder for indexing run after that, and a failure there still reaches you (a toast on the page, a notice box after the window). It moves the mail in Outlook only when the **Move to the Outlook archive folder when archiving** switch in Settings is on (`outlook.move_to_archive`, off unless set; the folder is `outlook.archive_folder`): after the save, the same move the `apply` verb makes, for received mail only (a filed Sent item stays in Sent Items, as with `apply`), run with the tag and the indexing so the window never waits for it; a move Outlook refuses is shown (a toast on the page, a notice box after the window) and logged, and the saved file stays. Each filing logs its per-stage timings (`file ms: attach=… scan=… save_msg=… attachments=… window_closed=… category=… move=… index=…`) to `outlook.log` in the runtime-data folder. A mail already in the index is refused, and the sheet says where it is filed; the **Archive a copy anyway** switch under that notice turns the button into **Archive a copy to …** and sends `duplicate: true`, so the copy takes the folder's next sequence number and nothing is overwritten (the Outlook bridge's `file` verb takes `--duplicate` for the same).

The **Outlook macro** puts the same flow on Outlook's ribbon. It starts `pythonw -m app.outlook archive --entry-id <id> --store-id <id>` hidden and returns at once, so Outlook never waits. The entry fetches the mail again by those ids, then opens a Tk window by default, even with the app open in a browser: `macro.prefer_window` (on unless set otherwise; the **Prefer the window over the web app** switch in Settings → Outlook macro saves it) skips the hand-off, so the entry also skips its wait for the app's answer. With the setting off, it hands the mail over before ranking any folder: a page open on this PC holds a poll open for it, so the sheet shows the mail at once and its folders follow when the server, whose index is warm, has ranked them, and the window opens only when no page is open. The entry logs which path it took and why. The window shows the same sheet, painted first and filled in from a background ranking: the match % with its rank, why and similar mail, an Open folder action per folder, the mail preview, **Find a folder**, a browsed other folder, a **Current Explorer folder** button (the same check and messages as the sheet), the category, the date prefix with the saved-as name and the already-archived notice with its copy choice. **Find a folder** searches every scanned folder with Quick search's own folder search (the same results for the same words, run in the bridge's process, so it works with the app closed): the email folders come first, and a folder outside them is listed greyed as **Outside the email folders**, to browse or open but never to file in. `↑`/`↓` pick a row, **Archive here** or Enter files the mail there at once with the window's category, copy and date-prefix choices (the same filer as the Archive button), **Open in Explorer** shows it in File Explorer, and `›`, **Subfolders ›** or `→` at the end of the box steps into its subfolders from the last scan (a breadcrumb names the way down; **← Back**, `←` at the start of the box or Backspace in an empty one steps back up). The window never grows past the monitor's work area: the found folders scroll (wheel, scrollbar, `↑`/`↓` keep the picked row in view) while **Archive here**, **Open in Explorer**, **Subfolders ›**, **Archive** and **Cancel** stay pinned at the bottom. It takes the app's white or dark tokens from `tokens.css` and follows the Windows app theme. Failures say which case they are: Outlook not reachable, no mail selected, the mail moved, no email folder mounted, pywin32 not installed.

- The sheet and the macro read the mail from Outlook, never a `.msg` from disk, and write only the filed `.msg` and its attachments inside `email.roots`.
- Every Outlook step runs `python -m app.outlook` in its own process with a timeout (the web server makes no COM call), attaches to the running Outlook and never starts one. The verbs log to `outlook.log` in the runtime-data folder, each with one `⏱️` line of per-stage milliseconds (start-up, attach, read, hand-off, window shown); the server's log has the ranking's own line and how long the mail and its folders took to reach the page. Those lines hold milliseconds and counts only.
- Needs `requirements-outlook.txt` (pywin32) and Outlook (classic); otherwise the card says why it is off. The new Outlook for Windows runs neither macros nor COM.
- `FOLDER_EXPLORER_OUTLOOK=off` keeps a process from starting the bridge at all (the e2e suite's disposable instance sets it).

Set the macro up once per PC:

1. Set the user environment variable `FOLDER_EXPLORER_HOME` to this checkout's folder. Settings → Outlook macro shows the exact `setx` line for this PC's checkout (a worktree resolves to its primary checkout) with a Copy button, and whether the variable is already set (read-only from the user environment; the app never runs `setx`). Open the sheet on the PC itself; other devices don't see the line.
2. In Outlook (classic), press Alt+F11, then **File → Import File…** and pick `assets/ArchiveMacro.bas` (or paste the text from Settings → Outlook macro → Copy into a new module).
3. **File → Options → Customize Ribbon**: add a custom group, choose **Macros** in "Choose commands from", add `ArchiveCurrentItem` and rename it **Archive**.
4. Restart Outlook so it reads the variable. If macros are blocked, allow them for this project in **Trust Center → Macro Settings** (or sign it with a self-made certificate from `SelfCert.exe`).

## Archive verbs (Outlook)

`python -m app.cli email batch <verb>` is the headless Outlook archive that task-os and life-os drive: `plan` (Inbox or Sent mail with ranked archive folders), `apply` (save a mail as `NNN - subject.msg` with its attachments into an email folder, move it to the Outlook archive folder and tag it), `revert`, `dismiss` (move without keeping a file), `renumber` (put a folder's sequence back in date order), `fix-cut-names` (rename mails whose name lost its first letters), `draft`, `read` and `send` (an unsent draft, sent only when its fingerprint matches the approved one), `mailboxes`, `find` (live Outlook folders, read-only) and `sync` (Send/Receive). Every verb prints one JSON document on stdout (`schema_version` 1) and logs to stderr and `email-batch.log` in the runtime-data folder; flags, error codes and exit codes are in `app/cli/email_batch.py`. `tests/archive/test_consumer_contract.py` replays every command shape the two apps send.

- The verbs write only inside `email.roots`: a destination, a file to delete or a folder to renumber anywhere else is refused per item. They read and write this app's own `emails.sqlite3`; the email stage still indexes new mail (`email index --root <folder>` after filing).
- `renumber` reads a `.msg` inside `email.roots` for its date (or, when mails share a number, its attachment names) only when the index has none, through `src/email/reader.py`; `fix-cut-names` reads each mail's subject there under the stage's download budget and lock, and neither starts Outlook.
- Outlook is reached over COM in the verb's own process, which the caller runs with a timeout. A closed Outlook is started visibly (`outlook.exe`), never as a hidden COM instance; Exchange senders resolve through `GetExchangeUser()`.
- `mailboxes.json` beside `config.json` (gitignored; `mailboxes.sample.json` is the template) lists the mailboxes `--mailbox` picks from; without it the verbs use Outlook's default store.
- Needs `requirements-outlook.txt` (pywin32); without it every Outlook verb answers `com_unavailable` and `mailboxes` reports each mailbox `unknown`. The suggester needs `rapidfuzz` (`requirements-email.txt`).
